# R04 encrypted snapshot core

Internal no_std Rust storage component; **not a completed or independently authorized vault**. The R04 W25Q64 two-bank adapter is [firmware/board/src/storage.rs](../../firmware/board/src/storage.rs), and a concrete STM32H573 SAES adapter is [firmware/target/src/vault_aead.rs](../../firmware/target/src/vault_aead.rs). The diagnostic image deliberately exposes neither vault operations nor a successful authorization path.

Each4KiB sector contains4080 bytes of AES-256-GCM ciphertext and a16-byte tag. The final plaintext chunk is zero padded. AAD binds the fixed format/domain, bank, total length, epoch, chunk index and useful length. Nonce is epochBE64||chunkBE32. A unique purpose-specific per-device key and durable nonrepeating epoch allocation are mandatory; cancellation and uncertain writes burn the reservation.

Two4MiB banks fit the physical8MiB NOR. Snapshot length is limited to1MiB without buffering the entire file in MCU RAM. The authenticated SE ledger holds the active bank/epoch/length and SHA256 commitment. The candidate [SE adapter](../se-state/README.md) implements its APDUs and commit protocol; actual persistence/ACL/boot integration remains unqualified. An ordinary Flash counter, missing object treated as empty, or host-selected root does not meet this contract. Test models exist only in test builds.

Replacement writes only the inactive bank, verifies every ciphertext readback, checks the exact approved plaintext digest and flushes before committing the protected head. A fresh mount verifies the complete ciphertext commitment. Any ambiguous/error state latches the instance. AEAD failure or authorization expiry zeroes the caller output before returning. Plaintext buffers owned by the core are zeroizing; callers must wipe their own outputs on lock and after use.

Every private read/replacement requires a protected-runtime `Checkpoint`; it checks the exact authorized request/channel, live device time, cancellation and hardware fault state before/after blocking steps and before final commit/output. This is not a substitute for fingerprint/PIN/device confirmation. No permissive production implementation is supplied. The commit must remain in the protected execution path; cancellation cannot undo an already-linearized durable commit or a genuinely ambiguous power loss.

The expected plaintext digest must be device-derived from the actual operation and bound to its fingerprint/confirmation request. The SHA256 ciphertext root is an integrity commitment anchored in the trusted SE ledger, not standalone authentication and not device identity.

Tests cover every model write/read/flush/commit cut including an acknowledged-uncertain committed head, partial-sector corruption, nonce reservations across reboot, full-image replay, chunk swapping, post-mount tampering, changed input digest, expiry during decryption and cancellation at each write checkpoint. These are model tests; actual SE atomicity, Flash power loss and SAES known-answer tests must be performed on the exact hardware.

`read_at` returns an exact bounded range and wipes all caller output if a later sector or checkpoint fails. `replace_from` supplies a scoped reader of the old committed snapshot while writing the inactive bank, using the same owned storage/crypto and live authorization. This permits [logical records](../device-records/README.md) to stream edits without duplicating a peripheral owner or holding the full snapshot. A full1MiB edit and every modeled read/write cut have regression coverage.

Known limits that block production qualification: no complete ledger/provisioning/authorization runtime integration yet; old ciphertext can remain in inactive sectors (no cryptographic secure-deletion claim); write extent and timing can reveal size/activity and need an explicit threat-model decision/mitigation; hardware masking, memory/EM leakage and fault resistance are unmeasured. The snapshot core does not implement credential/key lifecycle. Never use the fixed test AES key or test ledger for a real device.
