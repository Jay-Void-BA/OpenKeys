# SE持久状态：实现与实测前的约束

**现已有候选实现，尚未通过实片生产资格。** [openkeys-se-state](../crates/se-state/README.md)实现实际对象APDU、双head/提交锚点和持久生物重试适配，生产I/O接严格SCP03；普通NOR整数、测试RAM计数器或桌面状态没有生产后端。以下条件仍须在真实硬件上验证。

原始依据：[NXP AN12413](https://www.nxp.com/docs/en/application-note/AN12413.pdf)，Rev2.12，2021-03-24，PDF SHA256 `e98a72e4215ba2886d777509f066ff620925ae65999d9c28cbcf24b7f2cf5622`，§3.2.1.7、表45、99、105–107。该公开旧版规范允许1–8字节单调counter，达到上限后不能再增加；与所选E2实际applet版本及断电行为仍须交叉验证，不能由旧PDF推定实片资格。

1. **独立的预留epoch与提交锚点。** epoch必须先在SE持久增加，确认后才执行AEAD，取消/断电不退款。提交锚点必须在新密文与新head完整写入并校验后才单调增加。这两个状态不能混为“最后一个普通Flash版本号”。
2. **两个SE head槽加独立提交counter。** 仅用两个head槽并选择最大有效版本，无法区分“新提交写到一半”与“已经提交的新槽被破坏”，可能回退旧秘密。候选设计用提交counter明确选槽；选中槽损坏必须拒绝，不能自动找旧槽恢复访问。head中的SHA只能检测撕裂，真正的访问控制与防回滚仍由SE/配对/启动边界承担。
3. **原子点必须实测。** 新head写入/回读成功后才提交counter。最终counter应答不确定时锁住本次运行；重启后根据实际受保护counter选择完整旧版或新版，禁止自动重发/退款。SE counter在电源中断下的结果、对象耐久度及失败模式须有实际证据。
4. **持久类型与命名空间。** 检查counter宽度、BinaryFile长度和ReadType返回的PERSISTENT=01；不能接受临时对象。缺失/坏对象、6A88、断电丢失和未配对SE都是错误，不能解释为空白设备。明确受控初始化标记；已配对设备不能因backup/传感器/主控重置而自动重新初始化。
5. **策略和SCP mandate。** 每台独立ENC/MAC/DEK及应用密钥，确认四项SCP保护不可降级、对象无未授权删除/导出/重建途径、调试/固件回滚不可恢复默认keys。runtime不要提供原始SE、任意counter设置或对象创建接口。普通ReadObject/WriteBinary的成功不能自动证明对象策略正确。
6. **生物尝试与tag不是同一计数。** 先预扣失败预算，再保留该配对key下从未使用的16位tag；两步均确认后才发Identify。成功credit必须在认证匹配、请求/模板/tag检查及实时授权之后持久更新，不得重置tag总数。65535之前验证维护/轮换流程，耗尽后不得PIN回退。

I2C1的NACK进度判别已有有界Secure别名驱动，见[通信层说明](../crates/se-transport/README.md)与[芯片验证步骤](SE_I2C_REVIEW.md)。即使随后完成APDU编码，也必须用真实E2和FPC样件验证配对、读回、错误/断电及生命周期，之后才有依据接入完整认证运行时。现有诊断BIN不启用这些服务。

实现续更：指纹credit接口改为接收经可信帧验证器创建的`AuthenticatedMatch`，绑定预扣时的完整请求及tag，不能仅凭tag编号恢复重试次数。该类型仍依赖安装在保护域内的真实GCM/持久化提供者，不能把类型当作跨TrustZone或主机输入的认证证明。共享State/SAES服务在重入或密码错误后整体拒绝，密钥/状态不因新建轻量适配器而恢复。

当前候选策略为8次持久连续失败，取消/不确定写入也消耗预算；65535个tag永不回绕，PIN不能恢复。到限后的维护/恢复尚未实现，不应把这份原型策略直接烧成三把正式钥匙。公开[命名空间与初始记录](../manufacturing/se-state-layout.json)仅供制造审查，不含密钥，也不操作设备。
