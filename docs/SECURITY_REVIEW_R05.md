# R0.5 安全复查与未关闭事项

[状态](DEVELOPMENT_STATUS.md) · [会话与测试](PIN_SESSIONS_R05.md) · [制作 / 实物测试](../manufacturing/BUILD_R05_ZH.md)

**当前不能确认整机“理论上不易被攻破”。** 已补原生 PIN / 私钥接口与加密管理协议内核；生产 Root、可信启动配置、首次初始化 / 完整擦除和 USB / NFC / 管理器端到端集成仍未完成，存在足以阻止正式交付的软件缺口。电路检查、模型和依赖审计不能取代实物攻击评估，也不能保证抵抗所有攻击。

## 关键结论

1. **SE_EN 不是 PIN 验证器。** 已增加[原生 PIN v4](NATIVE_PIN_RUNTIME_R05.md)：私钥 / OTP 接口不再接受普通 SCP 类型，新签名策略只授权 PIN AuthID。旧 HKDF / MCU 比较后端不能转换成该私钥接口。但实际 ACL、PIN 对象不可删除重建、原生限次和初始化尚未资格验证，Root / 启动 / 隔离也未接通；不能宣称已实现整机独立硬件强制。见[原厂机制与旁路](SE_NATIVE_PIN_FEASIBILITY_R05.md)。
2. **六位 PIN 不抵挡离线提取。** 均匀随机组合约 19.9 位；生日、重复数更弱。假设计数不可绕过且完全未知均匀 PIN，11 次猜中概率约 11/1,000,000；该估计不覆盖侧信道、故障、泄露或重试绕过。擦除策略也允许持有设备的人制造拒绝服务。
3. **常数时间和认证芯片不等于整机抗侧信道认证。** PIN 在 GPIO 和 MCU 内仍有暴露；电源 / EM / 总线 / 屏幕可被观察或注入。随机延时和屏蔽不能独立证明安全。
4. **擦除锁存不等于擦除完成。** 当前代码持久阻止正常访问，但尚无删除 SE 所有私钥、OTP、协议 PIN、配对、Flash 密钥 / 目录 / staging 的受控原子流程。不得称为已完成“全清空”。
5. **管理器界面不等于安全管理通道。** 当前 GPUI 后端拒绝真实设备操作，手机 App 未交付；不能把占位按钮或 host Boolean 作为授权。
6. **传统算法仍待实片和固件集成。** 已将不支持 RSA 的 E2 换为 SE051C2HQ1/Z01XDZ / OEF A8FA / Applet 7.2 候选，保留原 H573 单 SE 架构。数据手册能力不证明真实 OpenPGP / PIV、长 APDU 或原生 PIN / ACL 已完成；见[选型依据](CLASSICAL_SE_POWER_R05.md)。[分版](EDITIONS.md)后 SM2 两版均排除，PQC 暂缓至 `pqc`；[旧双 SE 评估](DUAL_SE_REVIEW_R05.md)保留为历史研究，不是当前经典版的电路。
7. **无电池 USB 的辅助电源连接已修正，整机尚待验证。** U13 / C40 改接 SYS，C41 与新 C56 分别在 LDO 输出及 MCU VBAT 局部去耦。独立板网和距离检查通过，但 LCD 电压下限、最坏功耗、充电状态和真实认证流程仍须关闭，不能由这次电路修订推定整机已可用。

本轮源码复核还处理了：原签名对象策略对 AuthID 0 授权过宽；Noise X25519 适配未检
非贡献共享值；握手临时秘密 / HMAC pad 清零；把阻塞本地确认前的旧时间用于应答分片
期限；SE binary read 的 offset / length 成对编码。相应测试覆盖新增路径；这不是
“全部软件漏洞已经排除”的结论。UserID 通用 counter 不报告失败次数、ReadSize 不支持
UserID，也已作为原厂接口限制写入资格验证材料。

本轮经典 FIDO 复查又关闭了：[旧指纹入口、设备 PIN 与主机 PIN 混用、设置主机 PIN
之前取得的本地 UV token、锁定后的 token / 加密 PIN 重放、撤权返还连续错误预算、
公开 GetInfo 先读取私密目录、确认后未执行即延长租约](CLASSICAL_FIDO_PIN_R05.md)。
进一步补齐运行时验证失败和内核析构的完整撤权，防止重新设备解锁后复活旧主机 token。
相应独立客户端 v1 / v2 和负向测试已补；真实 H573 Root、SE ACL、IRQ / 时钟与
端到端管理仍未接通，因此不能将这些修复表述为整机理论安全或全部漏洞排除。

后续又将原生 PIN 对象与私钥交换能力拆开：[每次私钥 APDU 必须经同一活动 Execution
检查的端口](CLASSICAL_LIFECYCLE_R05.md)，失败时清输出并撤销执行 / 原生会话；只验证
一次 PIN 的对象不再能直接交给 Keys。新增实际 PIN 命名空间安装、全对象清点和两轮
全 NOR 擦除检查；安装阶段、对象观察和 NOR 回执都不能代表整机 Ready / 全清空。
生产 Root / journal / DeleteAll 恢复仍是阻塞项。

Root 密钥存储还须区分真实硬件状态：RM0481 Rev5 §3.8.3 的未处理防拆标志可能
使 DHUK 固定为 dummy 值，不能在这种状态下继续认证 journal 或解封密钥；不自动
清防拆标志恢复使用。Open 生命周期的问题是调试 / 数据保护未建立，不应把它与
上述 dummy 条件混淆。生产初始化必须核对生效的 TZ 状态、生命周期、调试与 TAMP，
不能只看 TZEN 选项字节或“调用了硬件唯一密钥”。已增加
[DHUK CMAC 与实际寄存器读取](../crates/h573-crypto/README.md)：前后双快照、每块复查、
固定 CBC 派生上下文、清除 KEYSEL 后复位、失败闭锁和 journal 域隔离适配。普通 CMAC
的 ECB→CBC 过程不能直接用于 DHUK，因为模式也是派生输入。模型使用独立密码库核对；
真实启动 / 选项字节 / TAMP 配置、受保护 Flash 接线和片上 KDF / 侧信道仍未验证。

现已补充[H573 内部日志 Flash 控制器与实际安全别名端口](../crates/root-flash/README.md)：
固定 bank2 末两个扇区、16字节写入、旧 EOP 与新完成区分、错误 / ECC 不清除、全读回、
异常控制状态不能静默修复成成功、卡住 / 未确认锁定时复位。模型与日志内核组合测试
覆盖逐调用中断、损坏及丢应答。STiRoT 交接的安全 Root 上下文已对齐 HDPL2；端口本身
不修改生命周期。生产链接 / 启动 / OTA 预留和 Root 配置尚未完成，诊断不调用它，
不能因此解除生产阻塞。新增[实物测试规程](../manufacturing/ROOT_STORAGE_TESTS_R05_ZH.md)。

## 放行前必须关闭

- 可信启动、签名升级、防回滚、生产调试配置、Root / SAU / GTZC / DMA / watchdog、可信时钟与 RTC。
- SE 实片身份 / KAT / 容量 / ACL / 生命周期、唯一随机配对、首次设置和完整擦除掉电恢复；没有公共默认秘密。
- FIDO CTAPHID / NFC、生产 Env、OpenPGP / PIV、SSH 各路径、OTP 导入与显示、加密记录与真实管理通道集成。
- 三桌面与三移动系统的实际构建、权限、认证与断连撤权；iPadOS 不宣称 NFC。
- LCD 电源 / 线束 / 复位、首板 / RF / 温升 / 电池 / EMC / ESD，SCA / FI / 拆机与修复复测。
- 固定提交、CI / 审计无告警、每台样机追溯和独立安全复核。

当前 [R04 对抗性复核](ADVERSARIAL_REVIEW_R04.md)仅用于共用模块历史追溯；其指纹 / 模板 / 四键和旧测试结果不是本版需求或安全结论。
