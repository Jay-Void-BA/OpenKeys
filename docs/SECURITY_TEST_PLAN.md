# OpenKeys：三把设备的安全验收方法

这是一份可执行的验收方案，不是认证证书。PCB 的 ERC/DRC、软件测试和仿真通过，都不能代替下面的实物验证。先使用没有真实账户、私钥和恢复码的测试设备；未通过的设备不要登记为唯一登录方式。

给三把设备分别标记 K01、K02、K03。记录 PCB/外壳版本、固件提交和二进制 SHA-256、SE/传感器料号、启动配置及测试日期。照片和日志只记录测试数据，不上传生产密钥、指纹模板、PIN、notes 或恢复码。

## 1. 你可以完成的检查

需要：带通断/电压档的万用表、不会主动请求高电压的 USB-C 电压电流表、合规 C-C 数据线、Apple 20W 充电器，以及三种桌面系统中实际可用的测试电脑。首次上电和电池装配建议让代工方完成，尤其不要自行焊接或拆改软包电芯。

| ID | 操作 | 通过条件与证据 |
|---|---|---|
| H01 | 未装电池时核对 J2 插头正负，测量 BAT/GND、USB 输入及 3.3V 是否短路。按 BOM 和装配图检查 IC 方向、LCD A/K、指纹排线 pin1。 | J2.1 为 BAT+，J2.2 为 GND；插头极性实际测量正确。不能只相信红黑线或 JST 外壳。保存代工检查记录。 |
| H02 | 代工方先用限流电源/电池模拟器启动，检查 SYS、3.3V、LCD_3V0、TAMP_3V0 和两个独立 VCAP。 | 所有电压符合对应芯片要求；无异常发热、振荡、连续复位。VCAP 不连接外部负载，绝不向 VCAP 注入高于其正常值的电压。记录波形和温度。 |
| H03 | 使用 Apple 20W 充电器和 C-C 线插入唯一 USB-C 母口，设备开关置 ON。观察空闲、背光和指纹工作时输入。 | 使用 5V，不发起 9V/更高 PD 请求。设计输入预算约 100mA/0.50W；电池充电目标 100mA，4.2V 时约 0.42W，系统负载会降低实际充电电流。这不是从充电器取 20W。 |
| H04 | 按电芯资料允许的环境充电，检查实际贴合电池的 NTC；由代工方模拟 NTC 开路、短路和温区越界。 | 充电停止或进入规定保护状态；不得用固定电阻替代真实电池温度检测。记录充电、截止、恢复过程。 |
| H05 | 关机、拔 USB，记录电池与备用域电流；静置后重新启动。 | VBAT/LSE/防拆状态连续。按实测电流计算维护充电周期；不能用额定容量直接承诺待机年限。完全失去备用电源不得自动恢复成可读取旧秘密的“新设备”。 |
| H06 | 用测试数据，分别在开机、主开关 OFF、拔 USB 后打开机壳，再合上并重启。 | 打开动作必须留痕并撤销授权；合上和断电不能清除该事件。故障后不能读取旧 notes、签名或导出秘密。分别保存三把设备的结果。 |
| U01 | 锁定状态连接管理器，扫描 USB，尝试列账户、notes 标题、恢复码和凭据。 | 只出现公开设备信息/解锁提示；私密元数据也不可见。管理器不得把 VID/PID 或序列号当作可信设备身份。 |
| U02 | 登记测试指纹；不使用指纹，仅按四键 PIN 或通过电脑输入 PIN。 | 所有私密操作拒绝。PIN 只是指纹之后的附加验证，不存在 PIN 备用解锁。手机系统指纹也不能替代设备传感器。 |
| U03 | 正确指纹后，分别测试错误 PIN、取消、超时、长按删除/取消、拔线、切换 USB/NFC、复位。 | 尝试预算先持久扣除，取消/断电不退款。长按不会再被算成一次短按；旧授权和旧确认不能继续使用。 |
| U04 | 显示一条测试 note，等待过期/取消/锁定；再触发 MCU 复位或机壳打开。 | 物理 LCD 上的秘密清除，不能只关闭背光。复位时独立开漏通路拉低 LCD_RESET_N；不依赖电脑刷新窗口。用录像或示波器记录。 |
| U05 | 用超长 RP ID、Punycode 域名、相似账户名和不同操作类型发起确认。翻阅全部页面后批准或取消。 | 不能静默截断、替换字符或隐藏决定性后缀；批准的操作、账户、通道和实际签名内容一致。U2F 只能显示可核对的应用标识哈希，不能捏造网站名称。 |
| F01 | 在测试网站分别注册 K01/K02/K03，测试用户验证 required/preferred、可发现凭据、选择和删除。 | 每把钥匙独立注册；私钥不靠复制 Flash 克隆。删除/管理必须再次验证设备指纹、附加 PIN 和确认。保存操作结果，不保存真实账户凭据。 |
| F02 | 分别用 macOS 浏览器 USB、iPhone Safari NFC、Linux 和 Windows 测试登录。 | 每个“系统＋浏览器＋接口＋协议”单独记录；某个 iOS 登录成功不能替代 NFC 管理、hmac-secret 或 SSH 的验证。 |
| F03 | 对同一测试凭据与 salt 调用 hmac-secret，再换 salt、凭据、设备和错误认证参数。 | 同一合法上下文得到稳定结果；跨凭据/设备隔离，错误参数与未验证指纹不返回派生秘密。使用支持该扩展的客户端，不把 TOTP 或 YubiKey HMAC-SHA1 当作同一功能。 |
| F04 | 使用实际支持 FIDO 的 OpenSSH 测试 `*-sk` 密钥和 Git SSH 签名。 | 每次签名仍需设备指纹和确认。macOS 自带 OpenSSH 的编译功能需核对，必要时测试 Homebrew OpenSSH；不能仅凭二进制名字判断兼容。 |
| M01 | 分别在三种桌面系统测试导入 notes/recovery codes、取消、删除、后台、锁屏、休眠和断线。 | 解锁前无私密内容；重新连接或唤醒不能复用过期授权。导入内容与设备确认绑定；OTP 输入明确拒绝。没有真实设备通道的开发管理器不能算本项通过。 |
| M02 | 若交付移动管理器，在真实 Android/iPhone 上分别测试 NFC 中途移开、APDU 分段、取消和会话重建。 | 认证加密会话和设备指纹均成立；半次写入不生效，旧 APDU/旧授权不能重放。模拟器或只有 NFC UI 不能算通过。 |
| M03 | 三系统各用合成记录录屏：有私密预览时启动导入，长时间停留原生选择器，切换窗口/锁屏/挂起；用慢盘、网络盘和取消后晚返回读取；重复取消以检查线程数。Unix另测符号链接/FIFO/设备文件，Windows测reparse point/NUL。 | 选择器创建前已有遮蔽帧；选择后必须重新指纹验证才读取；无私密标题/过滤词残留、无过期/跨授权结果；整批1 MiB/256条限制；未结束读取线程至多一个，UI不等待读取退出。真实后端未完成时只能记录模型测试通过，本项整机仍NOT_RUN。 |

## 2. 要求代工方或实验室完成的电气测试

让实验室按当前网表接线，在电池模拟器或受保护的测试电源上操作。不要拿安装锂电池的成品随意短接、过压或用自制高压枪放电。测试可损伤样机，报价和排期应包含这一点。

| ID | 接线与刺激 | 必须观察与通过条件 |
|---|---|---|
| E01 | 示波器同时测 3.3V、NRST、SE_EN、LCD_RESET_N；慢速升降电源并加入负载跃变。 | 供电越窗时独立复位和 SE 禁止使能，LCD 清除。测量实际阈值、延迟、振铃和恢复，不能只看软件 ADC 日志。 |
| E02 | 在受控 VBUS 故障源上测试 eFuse OVLO、浪涌、短路、反向电流及拔插；同时测保护前后电压、电流和温度。 | 后级所有引脚均不超出允许的瞬态/绝对额定条件，故障不能授予授权。现有 OVLO 直流角落约 5.56–5.84V，不等于瞬态输出峰值保证。 |
| E03 | USB 枚举、挂起、恢复、主机断电但电池仍在，重复至少 100 次。 | 挂起输入电流符合适用 USB 限值（设计目标不超过 2.5mA），停止充电/背光；不得通过数据、CC、SE 或 LCD 引脚反灌。 |
| E04 | 按 IEC 61000-4-2 进行放电；工程目标接触 ±8kV、空气 ±15kV，具体点位/次数由实验室确定。 | 允许安全复位，禁止错误签名、秘密泄漏、永久解锁、电池危险或保护失效。记录每个端口、极性和设备编号；这不是已有认证。 |
| E05 | 进行适用的辐射抗扰、传导抗扰和辐射发射预检；工程目标可先按 IEC 61000-4-3 10V/m 和 IEC 61000-4-6 3Vrms 制定。 | 在适用频段、USB 线和 NFC 工况下验证认证完整性；频段、调制、布置、接地和性能判据写入报告，不能只写“抗干扰通过”。 |
| E06 | 用 VNA/阻抗仪测装配前后、装壳后和人体握持时的天线；再用真实 NFC 手机验证。 | 验证谐振、负载 Q、失谐、距离、方向和传输错误率，按实测调整 C29。约 1.2µH 与 56pF 外接电容只是首轮模型，不能直接当量产调谐结果。 |
| E07 | 检查四键行程、LCD/FP 支撑、排线弯曲、USB 插拔和防拆触点预压；操作和温度循环后复测。 | 无压坏电芯、玻璃/排线受力、按键卡住、USB 松动或触点误闭合。外壳 CAD/图片本身不构成装配验证。 |

## 3. 故障注入与物理攻击

使用自己的测试钥匙和专用测试账户。可借用或委托拥有 ChipWhisperer/脉冲发生器、可调故障开关、示波器及近场探头的实验室。公开以下测试参数和结果摘要，保留原始波形；不要为了测试便利在生产固件中留下原始 SE/APDU、任意 GPIO 或解密命令。

1. **先建立负向对照。** 未验证指纹、错误指纹、错误 PIN、旧授权、错误固件和被修改 Flash，正常情况下均应拒绝。成功测试账户作为阳性对照，确保仪器确实能观察到正常签名。
2. **分别攻击各个电源域。** 对 MCU 3.3V、VCAP1、VCAP2、FP 电源和 SE 电源做受控降压。实验室制定电压/能量边界，禁止向 VCAP 灌入高于正常值的电压。扫描起始偏移、脉宽、深度、重复次数和设备温度；至少包含短于监控器响应的脉冲。
3. **不要误解 TPS3702。** 数据手册典型高到低传播延迟约 19µs，并没有据此给出的纳秒故障防护保证。短脉冲可能不引起外部复位；要检查芯片内部检测、启动链、认证验证与密钥使用是否仍安全。
4. **覆盖关键阶段。** 安全启动/签名验证、防回滚版本比较、指纹 GCM 验证、尝试预算持久提交、附加 PIN 比较、授权消费、SE 命令生成、vault 原子提交和升级切换均需被扫描。只在待机时拉低电压没有覆盖认证路径。
5. **判定成功必须具体。** 未经有效设备指纹取得一个有效 FIDO 签名、有效 hmac-secret、明文 note/recovery code、管理权限、调试权限，或启动旧/未签名固件，都算失败。复位、超时和拒绝不算绕过。
6. **重放指纹与总线。** 捕获自己设备上的加密测试帧，重放旧响应；分别修改 tag、nonce、密文、模板、长度及请求上下文。换 USB/NFC 通道、断电和回滚存储后重复。必须拒绝，且不能复用 GCM nonce 或回绕操作 tag。
7. **断电原子性。** 在持久预扣和写入各个边界断电，复测尝试次数、凭据、notes 和固件版本。未知写入状态必须拒绝，不能退款重试次数或回退到可访问的空白状态。
8. **主动尝试防拆绕过。** 在关机和开机情况下尝试短接触点、移除电池、从 LCD/按钮/USB 周围探入、拆传感器和外部 Flash。单个机壳触点可以被桥接，不能将它描述成经认证的主动防拆网格。若不破坏检测就能触达可信确认/密钥边界，本威胁等级尚未通过，应重新设计并复测。
9. **读保护和更新生命周期。** 由代工方在可牺牲样机上验证最终调试状态、恢复接口、ROM 启动路径、读保护及签名更新。测试错误签名、截断镜像、断电、降级和版本计数回滚。开发版可调试的结果不能替代生产状态；不要在未验证配置时直接烧写不可逆锁定。

扫描多少次、覆盖哪些范围都必须记录。未观察到绕过只支持该样本和范围，不能证明不存在所有硬件攻击。

## 4. 侧信道测试

| 测试 | 方法与判据 |
|---|---|
| 功耗/EM 固定对随机 | 在固定钥匙和随机输入两组下采集至少各 50,000 条对齐轨迹，覆盖 SE 运算、指纹认证、PIN 校验、vault 解密和派生。独立重复并记录三把设备差异。Welch t 检验常用筛查阈值为 \|t\| > 4.5；越界需分析，未越界也不是无泄漏证明。 |
| CPA/特定泄漏 | 针对实际算法和泄漏位置进行分析；包括 SE 总线、MCU 中的会话/派生材料、存储访问和错误处理。不能只测试“私钥没有通过 USB 输出”。 |
| 时序与错误差异 | 分离人工按指纹的时间，比较等长正确/错误标签、不同错误 PIN、找不到对象和认证失败的执行时间及响应。识别错误信息、重试计数或缓存形成的 oracle。 |
| 电磁/光学故障 | 按约定威胁等级对关键路径做 EMFI，必要时由有资质实验室评估开封/激光。滤波、金属屏蔽、随机延迟和 Rust 本身都不能代替这些证据。 |

SE 的芯片认证只覆盖其具体型号、版本和认证范围。MCU、配对密钥策略、传感器、PCB、显示确认、外壳和固件组合不会自动获得相同认证。

## 5. 软件验证与发布记录

在干净环境针对确切提交运行格式检查、Clippy `-D warnings`、单元/集成测试、目标固件编译和依赖审计。对 USB HID/CTAP CBOR、NFC APDU、管理帧、升级包、导入解析和掉电存储恢复做有界 fuzz；同时验证上限、重复字段、分段、序号溢出、错误上下文与取消路径。模拟后端只算模型测试，不能记为实机通过。

发布表逐项记录 `PASS / FAIL / NOT_RUN`，附测试提交、镜像哈希、设备编号、仪器/工具版本、步骤和证据路径。三把设备都须通过功能、电源、防拆和生产生命周期验收；物理攻击评估的样本与外推限制单列。CI 绿灯和零 warnings 是构建条件，不能把 NOT_RUN 的硬件安全测试改成 PASS。

出现任何未授权成功、回滚放行、真实秘密出现在日志、坏包崩溃后持续解锁或防拆无痕，应立即停止真实密钥部署，保存证据、修复并对同一攻击与相关路径复测。

## 6. 新增SE/密码路径的实片复核

此节需经审查的Secure测试镜像及开发仪器；现有OPEN诊断镜像不包含秘密、SE或指纹服务，不能用于证明这些项目通过。测试镜像仅用公开KAT密钥，在可牺牲样件上运行，不得给生产接口留下任意寄存器/原始密码指令。

| ID | 方法 | 必须保留的结果 |
|---|---|---|
| C01 | 每把钥匙在上电、MCU复位、USB挂起唤醒后，用NIST AES/CMAC/GCM向量检查实际SAES。覆盖AES128/256、非零nonce、8字节AAD/12字节指纹体和48字节AAD/4080字节vault体。 | 与独立实现逐字节一致；不能只做同一错误算法的加解密往返。记录原始向量、输出、镜像哈希和芯片revision。 |
| C02 | 引导阶段核对Secure别名、GTZC Secure/privileged位、HSI48频率和AN4230 Rev15表3的H573参数；尝试错误锁定配置和Non-secure访问。 | 错误配置/归属拒绝私密服务；CR配置基值00F01E00、HTCR6A91、NSCR3AF66，ARDIS、时钟检测和锁按设计生效。不得通过删除错误检测来使测试通过。 |
| C03 | 在SAES初始化、key加载、AAD、payload、final和清理阶段，分别注入RNG/时钟/访问错误及卡住完成标志；结合内部TAMP事件测试。 | 输出/签名/解密均拒绝，LCD与SE进入安全状态；正常进度只清CCF，错误不能自动恢复为成功。擦除卡死使整机复位；复位后仍保留已配对/持久预算，不进入空白初始化。 |
| C04 | 用受控SE链路代理改变ATR长度、I/R序号、R-ACK、CRC、WTX次数、半帧NACK及SCP03握手/version/i、cipher/MAC/status；截断回复或在发送后立即断电。 | 总等待有上限；不确定的私密APDU不自动重发；坏MAC之前不解密；裸6A88/9000不成为可信空记录或解锁结果。所有请求计数只按真实持久语义变化。 |
| C05 | 让授权在CMAC、SE响应、CBC解密和vault解密之后过期/取消，换连接后重放旧请求。 | 即使密码运算成功，最终输出/提交检查仍拒绝；秘密不出现在USB/NFC、LCD、日志或错误报告。 |
| C06 | 复查芯片擦除、CMAC子密钥/XOR及临时RAM、SCP会话材料和指纹方向消息的实际功耗/EM泄漏。 | 与第4节相同，保留轨迹、样本数、攻击与外推范围。硬件AES带mask和模型KAT通过不能替代此测试。 |

独立模型复现可运行`cargo test -p openkeys-h573-crypto -p openkeys-scp03 -p openkeys-se-transport --locked`；它只用于源码回归，不将C01–C06改为PASS。

新增C07：对照[SE状态布局](../manufacturing/se-state-layout.json)，逐对象核对type、8字节counter宽度、PERSISTENT=01、head长度和marker；验证实际ACL及SCP强制，不能只核对公开marker。在每条nonce/重试预扣、head写入/回读、commit/credit更新指令前后切断SE及主控电源，核对旧/新状态和不退款。破坏被commit锚点选中的head后必须拒绝，不能自动回到另一个槽。八次失败/取消后，关机和PIN都不能恢复尝试；65535标签不可回绕。测试数据及损坏样本分开，全部实片结果当前NOT_RUN。

新增C08：在SCP、vault和指纹密码适配间切换并注入RNG/SAES故障和服务重入，验证所有共享适配器拒绝，旧实例/新轻量适配器均不能清除poison。对FPC安全帧同时验证GCM错误、有效GCM但错误请求/tag/模板、credit应答丢失，保证无授权证明、LCD秘密或有效签名输出。另测传感器重置/故障下的随机IV重复；接收侧tag防重放不能证明传感器RNG故障下仍安全。

新增C09：用仅含公开测试key的Secure候选镜像和逻辑分析仪，在三块板逐台记录FPC SPI3时序。核对Mode0/MSB/1MHz、CS低后>500µs首沿、整帧连续CS、IRQ空闲不发时钟；模拟半次传输、洪泛和deadline跨越。冻结SPI进度标志时，独立watchdog必须在规定上限重置，LCD/SE门控必须进入安全状态；reset引脚断开不能误报已复位。记录镜像/芯片revision、原始波形与复位上限。当前NOT_RUN。

新增C10：逐个核对HAL实际访问地址与SAU/IDAU/GTZC/GPIO/RCC/中断/DMA属性；测试NS/非特权读写、DMA请求、alias覆盖和中断路由。不得将整个0x40000000–0x4fffffff暴露给NS后仍假定FP/LCD/SE访问受保护，也不得仅凭HAL trustzone-secure功能名称记PASS。实际安全事务、非法访问fault和秘密不输出均须留证；当前NOT_RUN。

新增C12：对照schema2核对独立FidoSignature/SigningSlot对象和新marker；测试签名counter到u32上限、增量中各次APDU前后断电、预留槽后生成前断电及耗尽。不得回绕、退款、复用槽或把旧schema自动清零升级；签名计数不应触发整个notes区重写。实际SE容量、策略和非导出行为另测。

新增C13：在生产候选Root存在后，用合成1MiB数据测试流式编辑、越界/后扇区坏标签、跨namespace、空FIDO标记、错误notes/recovery记录及每个提交阶段断电。失败后整个调用输出和缓存索引关闭；只能保留完整旧版/新版。另测FIDO重置不会先删共用指纹再半途失败，notes与全局擦除的范围必须与设备确认文字一致。当前只有软件模型证据，整机仍NOT_RUN。
