## GitHub 拆分方式与权限限制

已尝试创建 `Jay-Void-BA/OpenKeys-PQC` 独立仓库及调用 fork 接口；当前 GitHub 集成
均返回 **403 `Resource not accessible by integration`**。浏览器控制也未能启动。
因此实际交付采用现有仓库的两个隔离分支，**没有宣称独立仓库或 GitHub 原生 fork 已创建**。
每个分支拥有完整祖先历史，后续取得创建仓库能力时可直接推送 `pqc` 到新仓库的 `main`，
无需重建项目、丢失作者记录或重写历史。

## 两版共用的安全要求

- 本地六位 PIN 只从钥匙十键输入；首次 6+6 设置。协议 PIN 独立，不能替代本地 PIN。
- 第 11 次完整错误或修改本地 PIN 清空全部用户秘密；取消未完成输入不扣次数。
- 硬件与协议 PIN 分别按同一认证会话缓存 30 秒；连接、NFC 场和保活不续期，断连 / 离场立即撤权。
- 敏感请求完整显示并实体确认；OTP 种子不可导出，六位码只在设备 LCD 显示。
- 可信启动、签名更新、防回滚、调试生命周期、供电 / 时钟 / 防拆与侧信道要求不变。
- 自研运行代码使用 Rust / Zig，GPUI 英文管理器；各桌面 / 移动平台分别验证。

## 变更与证据的隔离

经典版先关闭无电池 USB 辅助供电、传统算法覆盖、本地 PIN 初始化 / 全清空、Root、
协议和真实管理器集成等现有缺口。已将不支持 RSA 的 SE050E2 候选换为
[SE051C2 / OEF A8FA / Applet 7.2](CLASSICAL_SE_POWER_R05.md)，保留单 SE 架构；
实片 profile、逐算法固件、原生 PIN / ACL 和容量仍待验证，不能因此称已覆盖
CanoKey 所有传统功能。

后量子版不得把继承的经典版 PCB、诊断镜像或通过的基线 CI 标为已具备后量子能力。
候选方案、器件确认、原理图、PCB、固件和测试证据按实际提交分别冻结；正式升级方案
还须确认安全应用 / 库许可和三颗采购，而不是先画猜测的封装。

共用的安全修复应经过两版各自审查后同步，记录来源提交；不自动合并整版硬件、料号、
安全芯片 profile 或制造文件。发布与制造前核对[版本元数据](../edition.json)、分支、
板摘要和诊断清单。历史 CI 记录只证明其标明的源码，不代表新增功能或实物资格。
