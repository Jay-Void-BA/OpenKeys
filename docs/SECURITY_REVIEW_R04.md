## 仍须解决和验证的安全条件

1. **硬件强制指纹尚不能单凭电路宣称成立。** SE_EN门控只反映复位与主控请求。认证传感器协议、可信启动和TrustZone/GTZC/DMA归属必须实际部署，私密操作在同一保护域内消费单次凭据后执行，不允许主机/非安全域发原始SE、GCM、显示或GPIO指令。
2. **SE050及FPC的安全配对和持久预算没有实物证据。** 工厂测试密钥、默认SCP03密钥不可用于真实秘密。16位指纹操作tag不得回绕；耗尽、断电歧义和备用域丢失必须锁定，不能回退PIN或重新变成空白设备。密钥轮换与恢复流程必须在耗尽前验证。
3. **快故障注入仍是开放威胁。** TPS3702约19µs典型传播延迟不覆盖更短VCAP降压、时钟/EM/激光故障。外部比较器、Brownout、软件重复检查或Rust均不证明无旁路；参照测试计划扫描时间/幅度/脉宽，若产生无指纹签名或秘密输出即停用该版本。
4. **触点防拆可能被短接。** 结构没有经过验证的主动网格或不可绕过断电清除。电池拔除、backup丢失、保留电压、传感器替换、探针接触和调试恢复分别测试。禁止把“有开盖开关”写成抗所有物理攻击。
5. **侧信道未测。** SE私钥不可导出、常时代码和零化都是设计条件。功耗/近场EM/时序、编译优化和受控请求条件下泄漏仍需测量。TVLA筛查阴性不等于无泄漏，须结合攻击实验及密钥/模板保护评审。
6. **电源保护计算只覆盖已列DC角落。** 需实测eFuse动态越压、反灌、TVS/PPTC热与能量协调，USB枚举/休眠限流及Apple20W适配器5V下实际输入/充电电流。不能给成品充电功率贴0.42W保证值。
7. **软件当前范围不能冒充完整认证器。** 现有策略、导入解析和锁定桌面程序的测试仅覆盖其真实实现。完整CTAP、SE持久存储、认证管理通道、签名更新与实际ARM运行时须分别通过功能/负向/模糊测试；未实现的接口保持拒绝，不伪造成功。

未发现问题的有限测试不能得出“所有软件漏洞均已排除”。仓库记录可重现的工具、具体输入和测试范围；不提供自签的安全认证结论，不借用上游或芯片认证为本整机背书。

## 板级软件自查续更

- LCD驱动在通信失败、非法字符、锁定和对象释放时主动拉低复位，保持至少2ms，避免GPIO析构恢复浮空后保留可见文字。I/O故障在该实例内不可重新初始化解锁。总线ACK不是实际显示内容的光学证明，仍须U04实测。
- 四键只在稳定释放后产生一次短按或长按；组合键、场景切换残留按键、长采样中断和时钟回退会丢弃或锁住输入。Flash驱动在发送写命令前检查地址/长度/页边界，检查WEL，写后回读；这些不是AEAD持久vault或抗回滚实现。
- 桌面端发现仅凭`Instant`可能在部分系统休眠后延长显示授权，已增加独立墙钟期限/回退拒绝及帧间隔检查。设备端授权与USB挂起撤销仍是安全权威；这个修正不宣称覆盖所有OS的短休眠通知。
- 严格依赖扫描发现Cortex-M0.7.10依赖已归档`bare-metal`（RUSTSEC-2026-0110，维护警告）。已用明确记录的源码补丁移除该兼容层，改为维护中的critical-section token/Mutex，保留原PRIMASK及内存屏障后端；添加嵌套、线程互斥和异常释放测试。未通过审计忽略列表消除警告。补丁及许可证随源交付。
- ARM诊断ELF/BIN是真实目标代码，但不是安全启动/认证运行时；SE/指纹始终关闭，无充电服务、USB/NFC/FIDO或私密写入。不会把“可烧录”当作“可存真实秘密”。

## 加密存储与硬件AEAD续更

新增no_std双区快照核心及实际W25Q64区间适配：提交点之前只写非活动区；源摘要、密文回读和flush全部成功后才更新受保护head。模型逐点断电（含半写扇区及commit已生效但返回不确定）、完整旧快照重放、分块交换和写后篡改均作为负向案例。epoch必须由真实SE预扣且永不退款，不能用测试内存计数替代。

自查发现开始时检查授权不足以覆盖慢I/O；已增加强制Checkpoint，跨读写/加解密后重读实时状态，并在最终输出/提交前拒绝过期或取消。测试确认在解密完成后过期仍输出全零，在每个写入检查点取消均不改变旧head。实际Ledger提交必须保持在同一保护域；已经线性化的提交无法被事后取消“撤销”。

实际H573 SAES AES-256-GCM适配器已编写并进行目标编译/Clippy检查：先在私有零化缓冲中解密，常时核对tag后才复制明文；每次运算及释放时用IPRST清理硬件key状态，清理失败重置MCU。它要求受保护的独立vault密钥、正确外设/RAM/DMA归属及watchdog；不会由公开UID、默认常量或测试key生成生产密钥。尚无芯片KAT、波形或侧信道证据，编译通过不是这些条件的证明。

明确未解决：真实SE原子ledger和密钥配对、记录解析与授权集成、旧密文安全删除、大小/活动时序泄漏及全部物理侧信道/故障测试。它们仍阻止生产安全发布，不能被新的模型测试覆盖或自动豁免。

## SE与H573密码续更

后续对照厂商资料发现前述SAES适配所用HAL存在H573 IV映射/故障标志处理及通用RNG配置问题，已经由专用有界寄存器序列与检查型RNG替换，不能继续把旧路径的“编译通过”当作密码行为证据。新增严格T=1和SCP03组合，要求四项保护、实时检查及异常终止；全部参考版本、修正、unsafe MMIO例外和未执行项目见[专项核查](H573_CRYPTO_REVIEW.md)。

桌面端还有一个真实后端启用前必须解决的风险：当前原生文件对话框及文件读取在UI线程同步运行，会阻塞帧驱动的清屏/超时处理；仅在返回后检查期限不足以保证等待期间的隐私。当前生产路径始终拒绝解锁，因此不能进入真实秘密导入，但不能把这种不可达性当作未来后端已安全。启用后端前须改为非阻塞处理或经实机验证的预先遮蔽/重新授权流程，并验证焦点丢失、挂起、慢磁盘、取消和过期结果丢弃；不得以保持当前同步路径换取表面功能完成。
