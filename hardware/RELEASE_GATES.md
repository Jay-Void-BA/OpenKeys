# 不可跳过的发布门槛

目前所有项目均未通过实物验收。成本目标不能替代这些安全要求。

| 阻断项 | 放行所需证据 |
|---|---|
| 可信指纹 | 精确料号、小批量供货、可交付 SDK/协议许可；设备与模块双向认证、防重放、固件和模板保护；传感器替换/总线注入测试。普通 UART/SPI 的 match=true 不能单独置UV |
| 完整固件 | Rust 的启动/升级/存储/SE/USB/NFC/屏幕/指纹端适配；协议负向测试。现有授权库不是可烧录设备固件 |
| MCU 生命周期 | 对照精确芯片修订与安全手册验证隔离、签名启动/更新、防降级、调试/工厂模式封闭；具体熔丝/锁定方案评审后在测试板验证，不能直接套用不可逆锁定命令 |
| SE 与恢复 | 每台独立配对密钥、正确对象策略/容量与原子计数；FIDO与HMAC根不导出；设备PIN失败计数断电/回滚不复活；新增/删除指纹和恢复不能旁路 |
| PCB 制造 | 精确器件/封装选定；完成布局布线、叠层/阻抗、回流/热/电源/EMI/RF评审；ERC/DRC清单逐项处理后再导出Gerber与贴片坐标 |
| 机械装配 | 打印装配核对屏幕/FP/电池/USB/按键高度、绝缘、应力、公差、跌落；电池额定电流/保护/NTC与充电最差条件验证 |
| 干扰安全 | ESD及适用辐射/传导抗扰项目；欠压/毛刺/复位始终拒绝或中止，不能误签、误解锁、丢计数或恢复旧授权；TVS额定值/泄漏/钳位与器件绝对额定值协调 |
| 侧信道/故障 | 精确PCB/芯片/固件版本的功耗、EM、时序评估与攻击实验；电压/时钟/EM故障注入按威胁模型验证。需要时另评估开封/激光；TVLA不显著不代表不存在攻击 |
| NFC 与平台 | 最终壳体天线实测；iOS Safari/目标App、USB/NFC逐项FIDO/U2F/PIN/UV/hmac-secret互操作；屏幕+指纹的超时/keepalive/电池低电量测试 |
| 三平台软件 | 真设备身份与认证加密通道、最小权限；仅导入选中项；锁屏/拔插/休眠清缓存；Mac/Win/Linux实机包与签名、公证/更新流程 |

FIDO认证、安全芯片认证、EMC测试分别有自己的范围。没有证据时不标称“已抗侧信道”“绝对安全”或“已获得FIDO认证”。SE内部ROM/applet仍为厂商提供，整个芯片并非开源实现。
