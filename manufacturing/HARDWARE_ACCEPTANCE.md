# 你需要执行的硬件验收

这是 K01、K02、K03 的执行入口。软件与图纸继续由项目完善；本文件把必须在实物上完成的工作交给你、代焊厂和实验室。当前只有电气诊断镜像，**端到端认证与攻击测试须等生产候选固件存在后执行**，不能拿诊断画面记为通过。详细判据见[安全测试计划](../docs/SECURITY_TEST_PLAN.md)。

## 1. 先做一块样板

先取得工厂对[个人及小批量委托](REQUEST_FOR_CONFIRMATION.md)的书面确认，再约定首板和其余设备的数量、费用及工序。实验室另确认个人受理和各专项所需样品数，不能把候选技术能力当作已经接受委托。

把 [R04制造包](../hardware/r04/exports/OpenKeys-fabrication.zip)、[BOM](../hardware/r04/BOM.csv)、[贴片坐标](../hardware/r04/exports/OpenKeys-SMD-position.csv)、[尺寸图](../hardware/r04/exports/OpenKeys-dimensions.pdf)及[关键器件表](critical-parts.csv)交给代焊厂。要求核对实际物料、封装方向、底部焊盘和指纹排线接触面，先装一块确认，验证后再完成另外两块。不要把 EVT 选型当成量产放行。

工厂应提供带限流的台式电源、电池模拟器、万用表、示波器、显微镜及 SWD 调试器。你自己准备 Apple20W USB-C 充电器、合规 C-C 数据线、只测量而不主动触发高压的 USB 表、Mac 和待测 iPhone。Windows/Linux 可借电脑；无需为了三把钥匙购买 EMC 或故障注入仪器。

不装电芯先检查 J2.1=BAT+、J2.2=GND、短路、IC方向、LCD A/K、排线pin1和机壳间隙。插头极性必须实际测，不能只看线色。软包电芯由工厂装配，避免自己焊接、挤压或在接电芯状态下做故障注入。

## 2. 工厂完成上电和电源记录

按原理图用限流电源/电池模拟器上电，保存以下原始读数和波形，不能只交一张“亮屏成功”的照片：

| 检查 | 测量点和动作 | 验收依据 |
|---|---|---|
| 各电源域 | SYS、+3V3、LCD_3V0、TAMP_3V0、VCAP1、VCAP2；静态和背光/指纹负载跃变 | 各器件资料中的工作范围、纹波、启动顺序和热限制；VCAP不能接外部负载或灌入异常高压 |
| 独立复位 | 同时记录+3V3、NRST、SE_EN、LCD_RESET_N，缓慢升/降电压 | 窗口越界禁止SE并复位LCD；测出实际阈值和响应延迟，19µs典型值不是纳秒防护保证 |
| USB保护 | 受控输入源测eFuse前后电压、电流、温度、短路/反灌/拔插 | 5.56–5.84V是OVLO直流计算范围；瞬态后级不得超额定，也不得产生授权 |
| 充电 | Apple20W+C-C线，5V输入，空闲及正常工作；记录CC/CV、截止和温升 | 不请求9V/更高PD；输入预算100mA≈0.50W，电芯目标100mA，4.2V时≤0.42W，实际受系统负载影响 |
| 电池温度 | 真实NTC贴合500mAh受保护电芯；模拟开路/短路/越温 | 进入资料规定的停止充电状态；固定电阻不能代替NTC |
| 挂起/断电 | USB枚举、挂起、恢复及主机断电重复100次；测USB/备用域电流 | 停充电/背光，不反灌；适用USB挂起限值需实测。诊断固件默认禁止充电，不能用于验证正常充电服务 |
| 防拆/结构 | ON、OFF、仅电池三种状态打开/合上外壳；检查电芯、排线、LCD及触点预压 | 事件持久留痕并清屏/撤权；合盖或断电不能解锁。普通触点可被桥接，不能宣称抵抗一切开壳攻击 |

## 3. 装壳后的接口和认证

工厂用 VNA 测线圈并在**最终装壳、电池和手握状态**调谐，再做手机测试。C29=56pF只是初始值，不能照抄仿真频点就认定 NFC 合格。

每把钥匙分别跑[测试计划](../docs/SECURITY_TEST_PLAN.md)的 U01–U05、F01–F04、M01–M03：未指纹、只输PIN、错误PIN、取消/超时/拔线、长RP分页、多账户选择/删除、hmac-secret、notes/recovery导入与锁定清屏。用合成数据分别记录 macOS/Windows/Linux USB 与 iPhone NFC；手机登录成功不代表手机管理功能也通过。签名必须由外部客户端验签，不能只相信设备自己显示“Success”。

SE I2C 的地址忙/数据NACK/中途断电另按[7项总线实测步骤](../docs/SE_I2C_REVIEW.md)执行。SE对象、计数原子性、指纹加密配对、重放和密钥不导出，按 C07–C11 逐项保留逻辑分析仪波形。新SE签名/HKDF适配还要核对实际曲线类型、对象策略、RFC5869已知向量、非导出和错误签名拒绝。

## 4. 委托实验室做攻击与抗干扰

把 E01–E07 和“故障注入与物理攻击”章节交给实验室，要求报价说明仪器、波形/频段/温度、扫描范围、次数、成功判据和未覆盖项。包括 ESD、辐射/传导抗扰、电源跌落、MCU/VCAP/SE/FP各域故障、时钟/EM故障、SCP/指纹总线重放、备用域丢失、调试关闭及签名更新/降级。

侧信道至少覆盖 SE 签名、MCU SAES、SCP03、指纹GCM、PIN和vault路径，交付原始功耗/近场采样、固定/随机分组依据和统计/攻击分析。TVLA未见泄漏不等于不存在泄漏；还应说明实际密钥恢复攻击尝试的预算。任何未经有效设备指纹得到有效签名、派生秘密或私密明文均判失败，安全复位不算绕过。

**三把日用设备不够同时承担破坏性资格测试。** 可以先借工厂测试板或另做可牺牲工程样品；不要在保存真实账户凭据的三把钥匙上做高能量或破坏性测试。当前不承诺一个未报价的安全测试总价。

## 5. 把这些结果交回来

每项提供：设备K01/K02/K03或工程样品编号、PCB/器件修订、固件提交与BIN SHA256、启动/生命周期配置、仪器型号/版本、接线照片、输入参数、原始CSV/波形/日志、PASS/FAIL/NOT_RUN及理由。PIN、真实指纹模板、配对密钥和恢复码不要上传GitHub。

用测试数据通过全部功能后才登记真实账户，三把分别注册，线下另存恢复方式。工程样品的物理攻击结论需写清能外推到哪些日用设备。最终生产镜像/安装包、逐台验收及人工签署共同构成交付；CI和本文件本身不会自动签发安全认证。
