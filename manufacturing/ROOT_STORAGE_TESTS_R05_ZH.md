# R05 Root 密钥与内部日志实测

[制作手册](BUILD_R05_ZH.md) · [Flash 控制器](../crates/root-flash/README.md) · [DHUK](../crates/h573-crypto/README.md) · [安全缺口](../docs/SECURITY_REVIEW_R05.md)

**尚未具备执行全部步骤的生产 Root 镜像。** 下面是首板 / 实验室的验收规程，
不是已通过记录。完成可信启动、生产内存图和必要的测试镜像后，用独立工程样品和
合成数据执行；不要先给最终三把写入真实账号秘密。记录固件 SHA、芯片批次、仪器、
每次注入参数和结果，K01 / K02 / K03 最终还须逐台验收。

## 先验条件

1. 生产启动 / OTA / 数据槽 / 修复擦除范围明确排除 bank2 的126、127扇区；同时检查
   `0x081FC000..0x081FFFFF` 和 `0x0C1FC000..0x0C1FFFFF` 别名。不要把“驱动地址固定”
   当作链接器与升级器已经排除这些范围的证据。
2. 由签名测试 Root 读取并核对生效的 STiRoT、TZ、HDPL2、SEC_EPOCH、Secure / privileged
   watermark / 块属性、SRAM 复位清除 / ECC、TAMP 和调试状态。关闭 / 锁定生命周期的
   不可逆设置应在独立样品上按原厂流程操作；本仓库诊断不自动烧写这些设置。
3. 测试 Flash 时禁用并等待 ICACHE / DCACHE 静止；确认实际总线读回不是缓存旧值。
   看门狗、供电与复位互锁先通过公开电气测试。所有测试默认保持外部私钥入口关闭。

## 功能与掉电

| 测试 | 操作 | 合格条件 |
|---|---|---|
| 边界 | 首 / 末 phrase、非对齐 / 越界 / 另一个 bank 请求；同时放置邻区 canary | 只允许两个指定扇区；邻区逐字节未改；非法请求闭锁 |
| 完成语义 | 预先留下旧 EOP；测试写入、单扇区擦除、写后独立读取 | 不用旧 EOP 承认完成；每次 relock；全扇区回读；无 FW / bank / mass erase |
| phrase 中断 | 在四次32位写入与完成之间扫描断电 / NRST / 毛刺时刻 | 无部分写回补 / 自动重试；重启拒绝损坏日志，不回退旧 Ready |
| 日志中断 | 覆盖 plan body / MAC / seal、另一扇区 erase、head body / seal | 只恢复已完整认证的精确 metadata 目标；不跳过 SE / NOR / Root 擦除步骤 |
| 假应答 / 总线故障 | 丢失 ACK、写缓冲非空、完成缺失、读回末字节异常 | 没有成功回执 / 用户数据输出；锁定无法确认或控制器卡住时整机复位 |
| ECC | 按 ST 支持的测试方法引入单 / 双位 ECC 故障 | 单位纠错同样拒绝；双位 NMI 进入故障复位 / 互锁；不清标志继续认证 |
| 旧快照 | 回放旧 NOR；独立评估旧 MCU 两页快照、SE owner 不匹配 | HUK MAC 不能单独防整对回放；旧 owner 拒绝，旧 SE 根不存在时不能恢复旧用户数据 |

**不要为了测试而在量产路径开放任意地址、原始 APDU、主机提交设备 PIN 或状态绕过。
测试构建不能作为最终签名发布镜像。** 若需要内部追踪点，验收时须核对其已移除，
并复测最终优化后的二进制；测试构建的结果不能直接替代最终构建。

## DHUK / 篡改与故障

在同一合法上下文用固定的内部合成记录重复认证，跨复位比较结果；另一颗芯片应得到
不同设备结果。不要读取硬件密钥，也不要提供对任意主机消息的 MAC 服务。
分别检查 KEYSEL / KEYVALID 结束状态、RNG 错误、上下文变化、未完成 SRAM 擦除、
TAMP 标志、BKBLOCK、强制零 EPOCH、HDPL / next-HDPL、调试连接与芯片退级。
任何异常都应拒绝日志认证；不得自动清 TAMP 标志恢复旧秘密。普通公开 AES 测试向量
可核对 SAES 字序和模式，但不能验证不可导出 DHUK 的实际派生函数。

实验室应在最终优化构建上对 SAES、CMAC 子密钥 / XOR / RAM、PIN 输入 / 验证、SE
命令和整机总线分别采集功耗 / 电磁轨迹，做固定与随机输入的统计泄漏筛查、重复复位
采样、针对性模板 / 密钥恢复尝试及电压 / 时钟 / EM 故障注入。记录样本数、对齐方法、
滤波、带宽和统计方法；未发现泄漏不等于已证明无法恢复密钥。任何可绕过 PIN / 限次、
恢复旧用户状态、输出不受控秘密或破坏签名 / MAC 结果完整性的发现都阻止放行。

通过后仍需完整认证器的 USB / NFC / 协议 / 管理器端到端测试；这份规程只覆盖 Root
密钥和持久化的一部分，不能声明“所有可能硬件攻击”或“全部软件漏洞”已经排除。
