# R05 NFC 隔离与断电反灌实板测试

[电路依据](../docs/CLASSICAL_NFC_ISOLATION_R05.md) · [备份防拆测试](BACKUP_TAMPER_TESTS_R05_ZH.md) · [制作手册](BUILD_R05_ZH.md)

当前全部 **NOT_RUN**。对应 U29/U30 五路 TMUX1511、U31 LM66100 和 R69=9.1k
的 209 位 BOM。软件协议测试必须等生产 Root、可信时间 / IRQ 和真实传输驱动完成；
当前公开诊断镜像不启用 NFC 或任何私钥服务，不能用于证明以下协议项目通过。

先用工程样机和合成秘密。记录提交 SHA、PCB 摘要、器件批次、供电拓扑、温度、
外壳 / 电池 / LCD 状态、手机 / 读卡器型号、探头负载和原始波形。高场强、注入与
ESD 使用合适的实验室夹具和限能设备，不能将外部电源直接与软包对顶。

## 测量边界

| 测点 | 物理位置 |
|---|---|
| 主 3.3V / NFC_VCC | U31.1 / U31.6（CE 为 U31.3，同 VOUT）；量正反向电流 |
| NFC_VOUT | U7.2 / C28.1；保持其独立，不把仪器供电误接入系统 |
| 五条主机线 | U29.3/5/12/10 分别为 CS/SCK/MOSI/MISO；U30.3 为 IRQ |
| 五条 RF 线 | U7.6/7/8/9/10；R70–R74.2 在 RF 侧，.1 在开关侧 |
| NRST / SE_EN / LCD | 同步观察复位、SE 失能及 LCD_VCC_SW 的锁存切电 |
| 备份域 | VBAT_BACKUP、主动防拆返回与原始驱动，确认 RF 不代替备份连续性 |

3.6V 是开关断电信号端的工作上限，不是高场强安全保证。漏电 ±2µA 的资料条件是
开关 VDD=0V，不可外推为 0–1.5V 的全区间漏电上界。20µA 总反灌 / 0.18382V 主轨
仅为待验证分配，不能填写为实测合格值。普通 10MΩ 探头会改变微安级测量结果。

## 验收矩阵

| 编号 | 操作 | 记录与拒绝条件 |
|---|---|---|
| N01 无电 RF | USB、主软包均不接，只保留健康备份；以读卡器 / 手机从无场到正常场，再由实验室覆盖约定强场范围 | 测主 3.3V、NFC_VCC、VOUT、五条 RF / 主机线电压和反向电流。主轨不能意外启动 MCU、抬高 SE_EN 或点亮旧秘密；不得超过每颗器件真实端口限值。超过分配、端口限值或资料不足，判 BLOCKED 并改板 |
| N02 每路边界 | 断电 / 复位低 / 正常上电三种条件下，使用限能夹具逐路施加数据手册范围内信号，同时观察其余四路 | 测串扰、反灌、IRQ 假脉冲、CS 毛刺。不能只量 VOUT 或只验证一个开关；没有铜线、备用通道或拉电阻绕过隔离。系列电阻不是钳位保护 |
| N03 部分供电 | 慢 / 快升降主 3.3V、USB 热插拔、空 / 无主电池、SW1 开关；RF 场在之前 / 期间 / 之后加入 | 连续捕获 0–1.5V 区域及 U31 反向关断瞬态电流 / 电荷、NRST、SE_EN、LCD 和备份域；不能仅用稳态微安值推断瞬态安全。任何旧 PIN 会话复活、复位释放即恢复私钥或残留秘密显示均失败 |
| N04 硬复位 | 发送 NFC 数据时保持 NRST 低；覆盖三个主动触点及独立 SW12 的复位路径 | 五路开关实际断开，软件 / 手机不能重新接通；SE_EN 低、LCD 锁存清除；释放复位不续期、不恢复旧授权。记录传播时间而非只看重启日志 |
| N05 SPI 与 IRQ | 首先 <=2MHz，跨电压 / 温度 / 不同负载；检查完整帧及极短 IRQ / CS 事件 | 测上升 / 下降、MISO 建立保持、开关延迟、330Ω 后的波形、IRQ 接收和超时。记录最大可靠速率，不能因单次通信成功就提高设计上限或放宽安全超时 |
| N06 管理会话 | 解锁后移走手机、RF 短失场、换手机、重连、并行 USB、重放和仅保活 | 真实 IRQ / 可信计时撤权。两种 PIN 仅同一已配对认证会话成功私密操作续期 30 秒，保活 / 连线 / 读电量不续期。协议错误、断连、换端和复位拒绝旧 token / 租约，敏感操作仍需实体确认 |
| N07 备份与抗拆 | 在主断电而 RF 仍存在时开盖、断备份、匹配波形桥接，再恢复 USB | RF 不把断备份变成新的工厂空白，不清 TAMP 或重播种来读取旧数据。必须隔离并执行独立受控销毁流程；桥接残余风险按备份防拆规程记录 |
| N08 故障与侧信道 | 由实验室组合 RF / 电压 / 时钟 / EM 故障与私钥、PIN、OTP 操作，包含复位释放边界 | 不跳过 PIN / 协议角色 / 请求确认，不泄露密钥或种子；OTP 码只在本机 LCD。除 TVLA 外进行模板 / 密钥恢复尝试；失败修复后对同一冻结版本复测 |

通过这些项目仍不等于抵抗所有硬件攻击。每项保存原始证据和失败复测，按确切
PCB / 固件 / 生产配置签字；没有生产软件、供应商完整电气资料或实验数据时保持未放行。
